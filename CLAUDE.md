# AI Document Assistant

Учебный fullstack-проект: RAG-ассистент по документам. Пользователь загружает документ,
приложение режет его на куски, считает эмбеддинги и отвечает на вопросы по содержимому со ссылками на источники.

**Стек:** NestJS + Prisma + PostgreSQL (pgvector) + OpenAI · React + TS + Vite (FSD) · JWT.

План и прогресс обучения — в [PROGRESS.md](PROGRESS.md). Шпаргалка по FSD — в [frontend/FSD.md](frontend/FSD.md).

## Режим работы (главное)

Это **обучающий** проект. Владелец репозитория — фронтендер, переходящий в фуллстек, и код он пишет сам.

- **Не писать за него код в `src/`.** Описывать задачу словами: что создать, по какому пути, какая логика,
  какие импорты/типы понадобятся. Готовые блоки кода — только если он застрял и попросил, или концепция встречается впервые.
- **Перед каждой задачей — «общая картина»:** что строим, зачем это нужно, как связано с целым. Не начинать с «создай файл X».
- **Ошибки — намёками, а не ответами.** Указать, где смотреть и какой сценарий прокрутить в голове; вывод он делает сам.
- **Каждое новое понятие требует пояснения при первом упоминании** — одной строкой простым языком или отсылкой к уже написанному им коду.
- **Отвечать по одному вопросу за раз**, начиная с самого базового; не вываливать всю картину сразу.
- Рутинные команды (`prisma migrate`, `start:dev`) он запускает сам. Claude запускает только диагностику.
- Стили, иконки, документация, `PROGRESS.md` — это Claude может писать сам.
- После каждого этапа — вопросы для самопроверки в `PROGRESS.md`; в начале следующего — мини-испытание на прошлый материал.

## Команды

Окружение — Windows + PowerShell. Docker Desktop должен быть запущен.

```
docker compose up -d              # Postgres + pgvector

cd backend
npm run start:dev                 # API на :3000
npx prisma migrate dev            # миграция + перегенерация клиента
npx prisma generate               # только клиент
npx prisma studio                 # веб-интерфейс к БД (:5555)
npx tsc --noEmit                  # проверка типов
npm run lint                      # eslint

cd frontend
npm run dev                       # Vite на :5173
npx tsc -p tsconfig.app.json --noEmit
npm run lint                      # oxlint
```

## Архитектура

**Бэкенд** — идиоматичный NestJS: фичевые модули (`auth`, `users`, `documents`, дальше `chat`),
`PrismaModule` глобальный. Правило «тонкий контроллер, толстый сервис»: контроллер только про HTTP,
вся логика в сервисе. FSD на бэкенд **не** распространяется.

**Фронтенд** — FSD: `app → pages → widgets → features → entities → shared`.
Импорты только вниз по слоям, снаружи слайса — только через его `index.ts`, внутри слайса — относительные пути.
Между слайсами одного слоя импортов нет. Алиас `@/` = `src/`.

Разделение api: чтение сущности — в `entities/*/api`, запросы ради действия пользователя — в `features/*/api`.

**Данные:** метаданные документа в БД, сам файл на диске в `UPLOAD_DIR`.
В БД два имени: `filename` (оригинальное, для человека) и `storedName` (uuid, на диске).
Инвариант: строка в БД = утверждение, что файл существует. Отсюда порядок операций —
при создании файл раньше записи, при удалении запись раньше файла.

## Грабли окружения

- **`curl` в PowerShell — алиас на `Invoke-WebRequest`.** Нужен `curl.exe`. И в окружении задан `HTTP_PROXY`,
  из-за которого локальные запросы уходят на прокси и возвращают 502 — добавляйте `--noproxy "*"`.
- **JSON в теле запроса из PowerShell.** Одинарные кавычки PowerShell снимает и до `curl.exe` внутренние `"` не доходят — прилетает `{"message":"Expected property name or '}' in JSON at position 1"}`. Форма `"{\"a\":1}"` ломается ещё раньше, `--%` тоже съедает кавычки. Работает единственный вариант: **одинарные кавычки снаружи + `\"` внутри** — `-d '{\"email\":\"a@b.ru\"}'`. Причина: строку парсят два разных разбирателя подряд — сначала PowerShell (одинарные кавычки оставляют содержимое как есть, включая обратные слэши), потом C-runtime самого exe (он превращает `\"` в `"`). Альтернатива для длинных тел — положить JSON в файл через here-string и передать `-d "@body.json"`.
- **Prisma 7** требует driver adapter (`@prisma/adapter-pg`), клиент генерируется в `backend/generated/prisma`
  с `moduleFormat = "cjs"`. Ошибка `Unknown argument` = клиент устарел, нужен `prisma generate`.
- На Windows, если `start:dev` запущен, он держит открытым бинарник query engine — `generate`
  (в том числе автоматический, внутри `migrate dev`) может молча не перезаписать его. Если после
  миграции `Unknown argument` не пропадает даже после рестарта — сначала останавливать `start:dev`,
  потом `migrate dev`/`generate`, потом запускать бэкенд заново.
- Классы Prisma для `instanceof` брать только из `generated/prisma`, не из `@prisma/client`.
- Колонки `embedding` нет в `schema.prisma` — она добавляется ручной SQL-миграцией (Prisma не знает тип `vector`).
- Истина о типах — терминал (`tsc`), а не подсветка в редакторе. При расхождении верить терминалу.
