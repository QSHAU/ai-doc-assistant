# AI Document Assistant — прогресс обучения

Учебный fullstack-проект: RAG-ассистент по документам.
Стек: **NestJS + Prisma + PostgreSQL (pgvector) + OpenAI** (бэкенд) · **React + TS + Vite, FSD** (фронтенд) · **JWT** (авторизация).

## Как учимся (метод 20/80)
1. **Обзор** — перед этапом: какие концепции встретим, как связаны (блок «Теория» в каждом этапе).
2. **Вдумчивое изучение** — разбираем каждый кусок кода: что, где, зачем.
3. **Практика** — код пишете вы сами, я объясняю и ревьюю.
4. **Повторение** — после этапа: «Самопроверка» (вопросы ≈ вопросы с собеседований) + мини-испытание на прошлый материал в начале следующего этапа.

**Уроки фронтенда 11.08.2026:** хук не разделяет состояние, а **создаёт** его — два вызова `useDocuments()` дают две независимые копии, поэтому список обновляет владелец, а форма лишь сообщает фактом (`onUploaded`) · рендер = повторный вызов тела компонента, **любой** рендер пересоздаёт функции; `useCallback` не отменяет ререндеры, а сохраняет **ссылку** — нужно для массивов зависимостей и `React.memo` · без `useCallback` в `useDocuments` был бы бесконечный цикл запросов (новая ссылка → `useEffect` считает зависимость изменившейся) · `target` (где родилось событие) vs `currentTarget` (чей обработчик выполняется); React **обнуляет `currentTarget`** после синхронной части — в асинхронном обработчике сохранять его в переменную до `await` · `disabled` при «нет файла **ИЛИ** идёт загрузка» — `||`, не `&&` · `<input type="file">` неуправляемый, значение из React не задать — сброс через `form.reset()` · `accept` — только UX, защита живёт на сервере

**Уроки бэкенда 11.08.2026:** multer декодирует имя файла из `Content-Disposition` как **latin1** (дефолт в `multer/index.js`) → кириллица бьётся ровно вдвое; лечится `defParamCharset: 'utf8'` · `.match()` возвращает массив или `null`, а не булево, и ищет **подстроку** → `application/pdf-malware` проходил · у `|` **самый низкий приоритет**: `^a|b$` читается как «начинается с a ИЛИ заканчивается на b» — якоря без скобок дыру не закрывают · пустой `Buffer` — объект, а значит **истинный**: ветка `if (!file.buffer)` в `FileTypeValidator` пустой файл не ловит · `fallbackToMimetype` = осознанный компромисс ради txt (сигнатуры нет) — мусор с заявленным `application/pdf` проходит валидацию, отсеет только парсер · абстрактный класс (нельзя инстанцировать; база даёт конструктор, `abstract`-методы требует с наследника) и дженерики `FileValidator<TOptions, TFile>` · `TFile = Express.Multer.File` вместо deep-импорта `IFile` (из `@nestjs/common` он не экспортируется — забыт в бочке `pipes/file/index.d.ts`) · переопределение может **ослаблять** требования к входу, но не ужесточать; TS пропускает и обязательный параметр вместо опционального (бивариантность методов) — гарантия тогда на программисте · библиотечный код обязан пережить любой вызов, прикладной вправе опираться на гарантии окружения — отсюда разный уровень паранойи · валидация в пайпе отрабатывает **до** тела контроллера → при отказе `writeFile` не случается, инвариант «строка в БД = файл существует» не нарушается · дешёвые валидаторы раньше дорогих (`ParseFilePipe` идёт по массиву и падает на первом)

Следствие: фронт сломан — форма ответа больше не массив.
